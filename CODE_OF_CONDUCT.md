# Code of Conduct

## Our commitment

We want Workload ABI to be a technical community where people can discuss difficult engineering trade-offs openly and respectfully.

Contributors, maintainers, reviewers, and users are expected to:

- be respectful and constructive;
- critique ideas and code rather than people;
- assume good faith while remaining rigorous about evidence;
- welcome newcomers and explain project conventions;
- avoid harassment, discrimination, threats, or personal attacks;
- respect privacy and security-sensitive disclosures.

## Technical disagreement

Strong disagreement is normal in an experimental specification project. Decisions should be driven by reproducibility, compatibility semantics, security, maintainability, and evidence rather than status or affiliation.

Vendor affiliation is welcome and should not determine whether a proposal is accepted. Workload ABI aims to remain vendor-neutral.

## Unacceptable behavior

Unacceptable behavior includes harassment, discriminatory language, doxxing, sexualized attention, sustained disruption, threats, deliberate disclosure of private security reports, or conduct that would reasonably make participation unsafe.

## Enforcement

Maintainers may edit or remove comments, reject contributions, temporarily restrict participation, or ban participants when necessary to protect the project community.

For sensitive conduct reports, use a private GitHub contact path rather than a public issue when available.

## Scope

This Code of Conduct applies in repository discussions, pull requests, issues, reviews, and other spaces where someone is representing the Workload ABI project.
